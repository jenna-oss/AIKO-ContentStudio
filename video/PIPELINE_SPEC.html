Internal Spec — v1

Topic-to-Video Pipeline

An automated pipeline that takes a topic as input and produces a finished, voiced, vertical video — the same process used by hand for the Mayweather, JPMorgan, DSCR, and construction-loan videos, now specified as a repeatable system. Orchestrated with the Workflow tool: judgment-heavy steps run as agent calls, deterministic steps (rendering, muxing, file checks) run as plain code between them.

00Input

topic (required) — a working title or short description, or a source URL/article when the topic is tied to a specific piece (like a specific blog post). Optional: brandFlag (whether to include client branding in the closer), target duration range.

01Research & Facts

agent · web search/fetch

Web-searches the topic, cross-checks 2–3 sources, extracts dated facts with citations. Flags when hard numbers are missing (as the construction-loan article did) rather than inventing them. Output shape matches the existing data/topics_*.json format.

02Hook + Script

agent reads hook_templates_1000.json + JS enforcement

When the brief has a locked opening line (every brief from the Plan page does), that line is beat 1, word for word, and the library is not used. The agent is told so, and the workflow script then puts the line in place itself: in the first batch, every script swapped the locked hook for a library one.

Otherwise, selects a category and a specific template from the 980-template hook library (hook_templates_1000.json — Educational, Storytelling, Authority, Myth Busting, Comparison, Day in the Life, Random), then fills its (insert X) placeholders with real facts from Stage 01. Example: "This represents your X before, during, and after X" → "This represents your credit score before, during, and after a DSCR loan."

Written for complete beginners. Research also returns the topic's key terms with plain-English meanings. The script explains each term the first time it's used, keeps to one idea per beat, and builds to a single takeaway. A separate agent then hears only the narration, as someone new to real estate investing would, and flags any unexplained term or confusing beat. The script gets one revision against what it flags, then a second listen.

In The Buy Box's voice. The script stage carries the brand guide's personality, voice and tone, with the guide's own "Say this / Not this" examples. The speaker is the person on the other side of the underwriting desk: experienced, beginner friendly and confident about the math, never superior, dumbed down or certain about the future. Scripts never mention Trilith or pitch a product, and the last beat asks the viewer to follow The Buy Box. A lint flags hype, talking down, promises about the future and a missing follow ask. Its notes go into the same single revision as the beginner check.

Writes the full 10–12 beat script (line + estSeconds per beat), same shape as data/script_*.json.

03Visual Plan

agent + JS validation

Gives each beat its own visual idea: what is on screen and how it moves, written for that line. There is no component library to pick from; scenes are designed from scratch so the videos keep their variety. Each beat also gets a background (black, white, concrete, or footage) and an accent: orange for the one thing to look at, green only for the answer, or none. Beats needing a real video clip are flagged for Stage 04.

The Buy Box rules: enforced, not suggested Checked in code, and the plan is sent back with the reasons if it fails any of these:
  • No two beats in a row share a background.
  • Footage exactly where a beat needs an asset.
  • The closing frame sits on black or white.
  • At least one scene uses Site Orange.
Text size is a floor, not a tier: headlines at least 110px, nothing under 40px.

04Asset Search

agent, per flagged beat

Searches Pexels' video endpoint only — this is a hard rule, not a preference: the search call itself is never allowed to hit the photo or GIF endpoints, so a static image can't enter the candidate pool in the first place. Uses 2–3 keyword variations derived from that beat's actual line (not one generic topic keyword). Returns 3–5 candidate clips per beat, ranked by relevance guess, for Stage 05 to work through in order.

05Asset QA

Two tiers, cheapest check first, so a bad candidate never reaches a model call it doesn't need.

Tier 1 — Format & motion deterministic, no model call
  • Must be a video file. Any non-video candidate is rejected before this tier even runs (Stage 04 only queries video search).
  • Extract 3 frames via ffmpeg (start / mid / end). Compute a perceptual difference between them.
  • Near-identical frames → static/boring clip → auto-reject, no vision call spent.
Tier 2 — Vision judgment agent call on the 3 sampled frames

The agent receives the 3 frames, the beat's specific line (not the general topic), and the on-screen caption. Structured output:

FieldChecks
relevantWould a viewer immediately connect this footage to this exact line? Generic topic-adjacent stock (e.g. handshake footage for any finance beat) fails even if thematically nearby.
visuallyInterestingReal composition and lighting, not the generic locked-off corporate-stock look; no dead space; no burned-in watermark or logo.
verticalCropOKWould a 9:16 cover crop cut off or squeeze out the interesting content?

relevant and visuallyInteresting are the real pass/fail gate. verticalCropOK is not — it routes the asset to a rendering mode instead of rejecting it (see below).

Crop failure ≠ rejection A clip that's relevant and interesting but doesn't survive a 9:16 cover crop isn't thrown away — Assembly renders it contained on black or white instead (the clip shown in full at its native aspect ratio, on a brand surface) rather than force-cropping it and losing the subject, or discarding a genuinely good asset over an aspect-ratio mismatch.
Retry & fallback On a relevant or visuallyInteresting reject, try the next candidate — up to 4 attempts per beat. If nothing passes, that beat falls back to a graphic-only scene (no photo/video). No silent settling for a clip that merely "sort of" fits — this was the exact failure mode that produced the disliked brick-wall photo before a human had to catch it by eye.

06Assembly

agent, writes the .tsx

Generates the actual Remotion composition file from the visual plan + script + approved asset paths. Every scene is written from scratch, for variety. What is shared is the brand, not layouts:

  • src/brand.ts: the colors, Archivo and Inter, the logo, the Reels safe zone and the text-size floors.
  • The word-synced src/Captions.tsx overlay.
  • A closing frame designed fresh each time, but always with the logo, the takeaway and "Follow @thebuyboxre".

Before rendering, the agent must pass brand-lint.mjs. It rejects:

  • off-palette colors, gradients, shadows and rounded corners
  • fonts other than Archivo and Inter, and text under 40px
  • a missing caption overlay, logo or follow ask
  • scene text that would collide with something: on top of the captions, below the safe zone under Instagram's controls, or more than 40px past its other edges. This is read from the component's real structure, so an offset inside a card or <SafeArea> is judged against that box, not the frame.

Text a little outside the safe zone passes with a note, rather than failing. That covers up to 40px past the top, left or right edge, or dipping into the gap above the captions without reaching them. The aim is the safe zone; the hard lines are only where overlap would happen.

Scene text goes inside <SafeArea> from brand.ts: the region inside the safe zone and above the captions. It is plumbing, not a layout; what goes in it is designed per scene.

CI runs it again and shows anything left as a warning. The new composition is registered in Root.tsx with a placeholder duration (corrected in Stage 07).

07Voiceover

agent, runs the ElevenLabs step

The timestamp-driven approach proven across the last three videos: one continuous ElevenLabs take with word-level alignment, real per-scene durations computed from the actual audio, then written back into the .tsx scene durations and Root.tsx's total duration — the video is timed to the voice, never the other way around.

08Render, Mux, Approval

agent, Remotion + ffmpeg

Final remotion render, ffmpeg mux of video + narration, then the finished file is returned for human approval — the pipeline does not auto-publish or auto-deliver anything. Same review gate used for every video so far.
